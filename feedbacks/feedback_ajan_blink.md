### **Meeting Summary: Ajan Blink, Ioon (Week 4)**

**Topic Focus: การวิเคราะห์สถาปัตยกรรม World Model และความท้าทายเรื่อง Extrapolation สำหรับสัตว์สูญพันธุ์**

**1. แนวคิดหลักและเปเปอร์อ้างอิงที่นำเสนอ (Core Concepts & References)**
ไออุ่นนำเสนอการสร้าง **Latent Action Space** เพื่อให้หุ่นยนต์ต่างรูปร่าง (Cross-Morphology) สามารถใช้ทักษะร่วมกันได้ โดยอ้างอิงจาก 2 เปเปอร์หลัก:
*   **เปเปอร์ที่ 1 (Dreamer):** ใช้ World Model พรีดิกต์ (Predict) เฟรมวิดีโอถัดไปในเกม (Next frame/state) เพื่อหาความสัมพันธ์โดยไม่ต้องให้เอเจนต์ลองผิดลองถูกเองทั้งหมด
*   **เปเปอร์ที่ 2:** การใช้ Laten Action Space สำหรับหุ่นยนต์แขนกล (Manipulators) โดยรวมชุดข้อมูลจากหลายๆ รูปแบบมาเทรนร่วมกันเพื่อหาภาษากลาง (Latent action) ผ่านโมเดล Inverse Dynamic Model (IDM) และ Forward Dynamic Model (FDM)

**2. แผนการทำงาน 2 เฟสที่ไออุ่นเสนอ (Proposed Pipeline)**
*   **Phase 1 (Pre-training):** ใช้ข้อมูลจากสัตว์ที่ยังมีชีวิตอยู่ (Relative animals) มาเทรน Inverse Dynamic Model และ Forward Dynamic Model เพื่อประกอบร่างเป็น "World Model"
*   **Phase 2 (Policy Training):** นำ World Model ที่ได้ ไปใช้เทรน Policy ให้กับหุ่นยนต์แบบ Unseen Morphology

**3. ประเด็นซักถามสุดเข้มข้นจากอาจารย์บลิ๊งค์ (Critical Q&A & Blueprint Defense)**
อาจารย์บลิ๊งค์ได้ตั้งคำถามเจาะลึกเพื่อเช็กความเข้าใจในสถาปัตยกรรม (System Overview) ของไออุ่นอย่างหนักหน่วง:
*   **คำถามเรื่อง "Inverse Dynamic Model" (IDM):** อาจารย์ถามว่า Input และ Output ของ IDM คืออะไร? ไออุ่นตอบว่า Input คือภาพวิดีโอ (เฟรม) แล้วฝังค่า (Embedding) ผ่าน Vision Transformer อาจารย์จึงแย้งว่า **ถ้าเป็นแค่การหาความสัมพันธ์ของภาพวิดีโอ ทำไมถึงเรียกว่า "Dynamic Model"?** เพราะคำว่า Dynamic ในทางหุ่นยนต์ควรต้องยุ่งเกี่ยวกับ Kinematics, ทอร์ค (Torque) หรือข้อต่อ (Joint space) โดยตรง อาจารย์สั่งให้ไปเช็กนิยามตรงนี้ให้ชัดเจน เพราะจะส่งผลต่อการดีไซน์ Input/Output ทั้งระบบ
*   **คำถามเรื่อง "World Model":** อาจารย์จี้ถามว่าสรุปแล้ว World Model ของงานนี้จะทำนาย (Predict) อะไรออกมา? (ทำนายเฟรมภาพ, ทำนาย Environment, หรือทำนายองศาข้อต่อ?) ไออุ่นตอบว่ามันทำนายออกมาเป็น Features ของเฟรมที่ถูกแปลงผ่าน Transformer ด้วย Neural Network แบบ MLP 
*   **จุดบกพร่องที่ต้องแก้ (Blueprint Flaw):** อาจารย์บลิ๊งค์คอมเมนต์ว่า การตอบ Input/Output ของระบบให้เคลียร์ไม่ได้ ถือเป็นข้อผิดพลาดร้ายแรงตั้งแต่การฟอร์มโจทย์ (Formulation) เพราะ **System Overview คือพิมพ์เขียว (Blueprint)** หากพิมพ์เขียวไม่ชัดเจน งานวิจัยนี้จะไม่สามารถเดินต่อหรือนำไปใช้งานใน Phase 2 ได้เลย

**4. โจทย์สุดท้าทาย: สัตว์สูญพันธุ์ (Extinct Animals) และหลักการ Extrapolation**
*   **Extrapolation ไม่ใช่ Interpolation:** การจะทำนายการเคลื่อนที่ของสัตว์สูญพันธุ์ (เช่น ไดโนเสาร์) ที่เรามีแค่ 3D โครงกระดูก เป็นการทำ **"Extrapolation"** (การทำนายข้อมูลที่อยู่นอกเหนือขอบเขตข้อมูลที่เคยเรียนรู้มา) ซึ่งยากมาก
*   **ปัจจัยในการทำนาย (Key Factors):** อาจารย์ถามว่าเราต้องใช้ปัจจัยอะไรบ้างในการทำนาย? ไออุ่นเสนอว่าใช้ตำแหน่งข้อต่อ โครงกระดูก และรอยเท้า (Footprints) 
*   **ความลึกของรอยเท้าสำคัญที่สุด:** อาจารย์เสริมให้เห็นภาพว่า "รอยเท้า" ไม่ได้บอกแค่ระยะก้าว แต่มันบอกถึง **ความลึก (Depth)** ซึ่งความลึกนี้เองที่จะทำให้เราคำนวณย้อนกลับไปหา **แรง (Force), มวล (Mass), และความเร็ว (Velocity)** ของไดโนเสาร์ขณะเหยียบลงไปได้ ข้อมูลเหล่านี้คือคีย์สำคัญที่ต้องนำมาใส่ในโมเดล

**5. แผนการทดสอบใน Simulation และข้อควรระวัง (Validation Setup)**
*   **การทดสอบด้วย Stick Insect:** ไออุ่นเสนอวิธีพิสูจน์คอนเซปต์ใน Phase 1 โดยการสร้างแมลง (Stick Insect) ใน Simulation 3 แบบ คือ **ขาสั้น, ขากลาง, ขายาว**
*   **วิธีของไออุ่น:** เทรนโมเดลด้วยแมลง "ขาสั้น" และ "ขายาว" แล้วนำโมเดลไปลองทำนายการเดินของแมลง "ขากลาง"
*   **คอมเมนต์แก้ไขจากอาจารย์:** อาจารย์บลิ๊งค์ชี้ให้เห็นว่า หากเรามีข้อมูลขาสั้นและขายาว การทายสิ่งตรงกลาง (ขากลาง) จะเป็นแค่การทำ **"Interpolation"** (การหาค่าในวิสัย) ไม่ใช่ Extrapolation ถ้าอยากจะทดสอบ Extrapolation จริงๆ จะต้องไปทำนายสิ่งที่ไม่เคยเห็นและอยู่นอกขอบเขต เช่น นำไปทายสัตว์ที่มีขนาดใหญ่กว่ามาก

**สรุป Action Item ของไออุ่นจากเซสชันนี้:**
ไออุ่นต้องกลับไปทบทวนและวาด System Overview ของ Phase 1 ใหม่ออกมาให้โคตรชัดเจน (Input คืออะไร, ผ่านโครงข่ายไหน, Output ออกมาเป็นหน่วยอะไร) และต้องตัดสินใจเลือกให้แน่ชัดว่าโจทย์นี้กำลังจะทำความท้าทายแบบ Interpolation หรือ Extrapolation กันแน่

จากการประชุม อาจารย์และทีมงานได้ให้คำแนะนำและข้อกำหนดที่สำคัญสำหรับการเตรียมตัวทำ Proposal (ซึ่งมีกำหนดส่งในวันที่ 7 ของเดือนหน้า) โดยสิ่งที่ทุกคนต้องทำเพื่อเตรียมเขียนรายงานมีดังนี้ครับ:

1. **ตกผลึกและเลือกหัวข้อวิจัย (Contribution Topic):** ขั้นตอนแรกคือทุกคนต้องตัดสินใจเลือกและเคาะหัวข้อ Contribution ของตัวเองให้ชัดเจน (เช่น IRL, Flow Matching หรือ World Model) เพื่อให้มีแกนหลักในการนำไปเขียนรายงาน
2. **สโคปเป้าหมายก้าวแรก (Milestone 1) ให้ชัดเจน:** อาจารย์แนะนำว่าไอเดียตั้งต้นมักจะมีความกว้างและฟุ้ง จึงต้องนำไอเดียไปปรึกษาและสโคปขอบเขตงานร่วมกับรุ่นพี่และอาจารย์ เพื่อดึง **"Milestone ที่ 1"** หรือเป้าหมายระยะสั้นที่สามารถทำสำเร็จได้จริงในระยะเวลาที่มีจำกัดออกมาให้ได้ก่อน
3. **วาดพิมพ์เขียวของระบบ (System Overview / RL Diagram):** เป็นจุดที่อาจารย์บลิ๊งค์และอาจารย์โก้เน้นย้ำอย่างหนักว่าต้องวาด **แผนภาพสถาปัตยกรรมระบบหรือไปป์ไลน์การทำงาน (Pipeline process)** ออกมาให้ชัดเจน โดยเฉพาะการนำแนวคิดไปแมป (Map) ลงในโครงสร้างมาตรฐานของ Reinforcement Learning (RL)
4. **กำหนด Input และ Output ของแต่ละบล็อกให้เคลียร์:** ในไดอะแกรมนั้นจะต้องระบุได้โคตรชัดเจนว่า แต่ละบล็อก/เน็ตเวิร์กทำหน้าที่อะไร **รับข้อมูล (Input) มาในรูปแบบใด และพ่นข้อมูล (Output) ออกมาเป็นหน่วยอะไร** หากไม่สามารถตอบจุดนี้ได้ อาจารย์บลิ๊งค์ชี้ว่าถือเป็นข้อบกพร่องร้ายแรงตั้งแต่การตั้งโจทย์ และงานวิจัยจะไม่สามารถไปต่อได้
5. **ออกแบบการสร้างข้อมูลและการวัดผล (Data Generation & Evaluation):** ต้องตอบให้ได้ว่าในเฟสแรกสุดของการทำงาน จะมีวิธีการได้มาซึ่งข้อมูลอย่างไร (เช่น ใช้ข้อมูลจาก Simulation แทนวิดีโอสัตว์จริง) และจะ**ใช้วิธีหรือตัวชี้วัด (Metrics) ใดในการวัดผล**ว่าโมเดลนั้นทำงานได้สำเร็จและถูกต้อง
6. **ทบทวนวรรณกรรมอ้างอิง (Literature Review):** ต้องไปค้นคว้าและอ่านเปเปอร์วิจัยที่เกี่ยวข้องกับแนวทางที่ตนเองเลือกอย่างละเอียด เพื่อให้เข้าใจรากฐานของวิธีการเหล่านั้นและนำมาสนับสนุน Proposal ของตัวเองได้
