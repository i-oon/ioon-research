### **Meeting Summary: Ajan Go, Ioon (Week 4)**

**Topic Focus: Cross-Morphology Transfer ด้วย Latent Action World Models**
ไออุ่นนำเสนอแนวคิดการแก้ปัญหาเรื่อง Reinforcement Learning (RL) ที่มักจะยึดติดกับรูปร่างของหุ่นยนต์ (Specific Morphology) โดยเสนอการใช้ **World Model** เข้ามาช่วยหา "ภาษากลาง" หรือ **Latent Action Space** เพื่อให้หุ่นยนต์ที่รูปร่างต่างกันสามารถแชร์ทักษะการเดินร่วมกันได้.

**1. เปเปอร์อ้างอิงและแนวคิดหลัก (Core Concepts)**
*   **Dreamer Model:** โมเดลที่ใช้จัดการกับวิดีโอเฟรม เพื่อหาสเปซร่วมกัน ทำให้สามารถทำนาย (Predict) อนาคตได้ล่วงหน้า ช่วยลดเวลาในการสุ่มพฤติกรรม (Computation Efficiency).
*   **Action Robot Foundation World Model:** การนำ Latent Action Space มาใช้รวมศูนย์ (Unify) ระหว่างแขนกล (Manipulators) หลายๆ รูปแบบ ซึ่งไออุ่นต้องการนำแนวคิดนี้มาประยุกต์ใช้กับ **หุ่นยนต์เดิน (Locomotion)** ซึ่งยังไม่มีใครทำ.

**2. โครงสร้างไปป์ไลน์ที่นำเสนอ (Proposed Pipeline)** แบ่งเป็น 2 เฟส:
*   **Phase 1: Pretraining (การสร้าง World Model)** 
    *   โมเดลจะเรียนรู้จากภาพเฟรมวิดีโอ (Observation) และ Action เพื่อสร้างโมเดลก้อนย่อย 2 ตัวคือ:
        1.  *Inverse Dynamic Model (IDM):* ทำหน้าที่แปลงความสัมพันธ์ระหว่างเฟรมให้กลายเป็นภาษากลาง (Latent Action).
        2.  *Forward Dynamic Model (FDM):* นำ Latent Action ไปทำนายสถานะในอนาคต (Next State).
*   **Phase 2: Policy Training**
    *   นำ FDM ที่เทรนเสร็จแล้ว มาช่วยบอก Next State และประเมิน Expected Reward ให้กับระบบ Actor-Critic.
    *   ใช้ **Action Projector** เพื่อแปลภาษากลาง (Latent Space) กลับไปเป็นคำสั่งข้อต่อ (Joint Command) ให้หุ่นยนต์แต่ละตัวนำไปใช้งานจริง.

**3. ข้อถกเถียงและปัญหาหลักที่พบจากการระดมสมอง (Debate & Challenges)**
*   **ปัญหาคอขวดที่ "Action Projector":** อาจารย์และรุ่นพี่ (พี่นาย/พี่แฮป) ตั้งคำถามหนักมากในจุดนี้ ว่าถ้าสุดท้ายแล้ว Policy และหุ่นยนต์ต้องการคำสั่งแบบ "Joint Space" (องศาข้อต่อ) ทำไมเราถึงต้องแปลงไปเป็น "Latent Space / Frame Space" ให้ซับซ้อนแล้วต้องมีตัวแปลงกลับอีกรอบ?. 
*   **ความยากของข้อมูลวิดีโอสัตว์จริง:** การไปหาวิดีโอสุนัขหรือแมลงจริงๆ มาหาค่า Action Space ที่แท้จริงเพื่อใช้เป็น Data นั้นทำได้ยากมาก และอาจจะใช้เทียบกับข้อต่อหุ่นยนต์ตรงๆ ไม่ได้.

**4. ข้อสรุปและแผนการปรับแก้ (Conclusion & Pivot Strategy)**
เพื่อเป็นการพิสูจน์คอนเซปต์ (Prove Concept) ในเบื้องต้นโดยไม่ต้องเจอปัญหาทางเทคนิคที่ซับซ้อนเกินไป อาจารย์และทีมงานจึงแนะนำให้ปรับลดสโคป (Simplify) ดังนี้:
*   **ทำทุกอย่างใน Simulation เท่านั้น:** เปลี่ยนจากการใช้วิดีโอสัตว์จริง มาเป็นการสร้างหุ่นยนต์ในซิมูเลชันแทน.
*   **สร้างโมเดลแมลง (Stick Insect) 3 รูปแบบ:** ให้ลองสร้างหุ่นยนต์แมลงที่มีความยาวขาต่างกันในซิมูเลชัน เช่น ขาสั้น, ขากลาง, และขายาว.
*   **วิธีทดสอบ (Validation):** 
    1. ให้ทำการเก็บข้อมูล (Data Collection) ท่าเดินจากแมลง **ขาสั้น** และ **ขายาว** นำไปเทรนเข้า World Model ใน Phase 1.
    2. นำ World Model ที่ได้ ไปทำนายและพยายามทำให้แมลง **ขากลาง** (ตัวที่ไม่เคยเห็นมาก่อน) สามารถเดินได้.
    3. นำ Latent Action ที่ได้มาทำ PCA ดูว่า Action จากหุ่นยนต์ที่ขาสั้นและยาว เกาะกลุ่ม (Cluster) ร่วมกันเป็นพฤติกรรมเดียวกันหรือไม่ เพื่อวัดผลว่าโมเดลเข้าใจภาษากลางจริงๆ.

**5. งานที่ต้องทำต่อไป (Action Items / Homework)**
*   ไออุ่นต้องกลับไปเขียนแผนภาพ (Pipeline Diagram) ของ **Phase 1** ให้ชัดเจนว่า Input และ Output คืออะไรกันแน่ และจะมีวิธีการสร้าง (Generate) รวมถึงการวัดผล (Measure) ข้อมูลเซ็ตนี้อย่างไร.

### **Week 5 Progress Update: Ioon (Cross-Morphology Transfer)**

**1. การปรับจูน Pipeline และโครงสร้างระบบ (System Architecture)**
*   **เปลี่ยนชื่อบล็อกเพื่อความเข้าใจที่ถูกต้อง:** เปลี่ยนชื่อจาก Inverse Dynamic Model เป็น **"Inverse Transition Model"** เพื่อป้องกันความเข้าใจผิด (Misleading) ว่ามันเกี่ยวข้องกับการคำนวณแรงทางฟิสิกส์ (Dynamics) ทั้งที่จริงมันแค่ทำงานกับข้อมูลภาพ
*   **กระบวนการทำงานของ Phase 1:**
    1.  รับข้อมูลภาพจาก **Camera Sensor (Third-person view)** และล็อกคำสั่งข้อต่อ (Joint command)
    2.  ส่งภาพเข้า **Visual Encoder** เพื่อสกัดออกมาเป็นตัวแปรฟีเจอร์ (Feature) โดยไออุ่นจะดึง Pre-trained model สำเร็จรูปที่เคยถูกเทรนด้วยรูปและวิดีโอทั่วไปกว่า 1 ล้านภาพมาประยุกต์ใช้งานเลย
    3.  ส่งฟีเจอร์เข้า **Inverse Transition Model** ซึ่งใช้กลไก **Attention Mechanism** ในการหาความสัมพันธ์ระหว่างเฟรม (State ปัจจุบันกับ State ถัดไป) เพื่อสกัดออกมาเป็น "ภาษากลาง" (Latent Action)
    4.  นำ Latent Action ไปทำนาย Feature ใน Time step ถัดไป (วนลูป) จนได้ World Model

**2. ขอบเขตการทดสอบและการตั้งค่า (Setup & Scope)**
*   **ใช้ Stick Insect 3 รูปแบบ:** ทำการทดสอบใน Simulation 100% โดยใช้โมเดลหุ่นยนต์แมลงแบบ ขาสั้น, ขากลาง, และขายาว
*   **โจทย์พฤติกรรม (Task):** ลดความซับซ้อนลง จะยังไม่ทำท่าทางการเดิน (Gait) ที่ซับซ้อน แต่จะทดสอบพฤติกรรมพื้นฐานก่อน เช่น การเดินตรง, การเลี้ยวซ้าย/ขวา, และการหยุดกะทันหัน
*   **การทดสอบ (Validation Plan):** จะฝึกสอน (Train) ข้อมูลด้วยแมลงขาสั้นและขายาว แล้วนำไปทดสอบแบบ "หาค่าในวิสัย" (Interpolation Test) กับแมลงขากลางก่อน หากสำเร็จจึงค่อยขยับไปทำ Extrapolation

**3. วิธีการประเมินผล (Evaluation Metrics)**
*   **การจับกลุ่มพฤติกรรม (Clustering):** จะใช้เทคนิคการกระจายตัวอย่าง **UMAP** (คล้าย PCA แต่จับความสัมพันธ์แบบ Non-linear ได้ดีกว่า) เพื่อพล็อตดูกราฟ
*   **เป้าหมาย:** คาดหวังว่าหากป้อนแอคชันเดียวกัน (เช่น ท่าเลี้ยวซ้าย) ของแมลงทั้ง 3 รูปแบบ กราฟจะต้อง **"เกาะกลุ่มกันเป็นพฤติกรรม"** โดยไม่ถูกแยกออกจากกันด้วยสรีระความยาวขาที่ต่างกัน (Morphology-independent)

**4. ข้อเสนอแนะสำคัญและสิ่งที่ต้องทำต่อ (Key Feedback & Action Items)**
*   **ต้องเช็กความต่างของสรีระให้ชัวร์ (Significant Morphology Check):** พี่แฮปเตือนว่า ต้องทดสอบให้แน่ใจก่อนว่าขาที่สั้นกับขาที่ยาว มันส่งผลกระทบต่อ Policy จริงๆ เพราะถ้าส่งคำสั่งเดียวกันแล้วหุ่นขาสั้นกับขายาวเดินได้เหมือนกันเป๊ะๆ การทดสอบนี้จะไม่มีความหมายเลย
*   **สมมติฐานเรื่องเวลาเทรน (Hypothesis on Training Time):** อาจารย์โก้ยกตัวอย่างเพื่อวัดผลว่า หากนำ Policy ท่าเดินขาสั้นไปใส่ให้ขายาว ขาอาจจะลากพื้นเพราะยกสูงไม่พอ สิ่งที่คาดหวังจาก World Model คือ มันต้องรู้และไปปรับ Policy ให้ขายาวยกสูงขึ้นเพื่อเดินให้ได้เหมือนขาสั้น **"โดยใช้เวลาในการเทรน (Training time) ที่ลดลงอย่างชัดเจน"** นี่คือมาตรวัดผลหลักว่า World Model มีประโยชน์จริง
*   **ห้ามรันรวดเดียว ต้องเทสทีละบล็อก (Component-by-Component Validation):** อาจารย์โก้และพี่แฮปสั่งให้ค่อยๆ ทดสอบไปทีละสเต็ป ห้ามเอาระบบมายำรวมกันแล้วรันทีเดียวเพราะจะหาบั๊กไม่เจอ โดยให้เริ่มเช็ก "Visual Encoder" เป็นอันดับแรกสุด ว่ามันสามารถแยกฟีเจอร์ของหุ่นยนต์ (High Relation) ออกจากฉากหลัง (Low Relation) ได้ถูกต้องจริงๆ ก่อนที่จะทำสเต็ปถัดไป
*   **นำโมเดลในแล็บมาใช้ (Resource Usage):** อาจารย์แนะนำให้ใช้โมเดล Stick Insect ที่มีอยู่แล้วของทีมวิจัย (ของอาจารย์ YuChen หรือพี่นาย) เพื่อให้ทำงานได้เร็วขึ้นและสามารถเชื่อมโยงผลลัพธ์กับคนอื่นในแล็บ (เช่น ของบีม) ได้ในอนาคต

**Homework สำหรับสัปดาห์ถัดไป:** ไออุ่นต้องกลับไปเขียน Timeline การทำงานให้ชัดเจน และเริ่มดำเนินการทดสอบบล็อกที่ 2 (Visual Encoder) เพื่อนำผลลัพธ์มาโชว์ในสัปดาห์หน้า

**Week 7 Progress Update: Ioon (Cross-Morphology Transfer)

**1. คำถามและข้อสงสัยหลักที่ต้องเตรียมตัวตอบ (Critical Questions for Defense)**
*   **คำถามจากพี่แฮป (เรื่องประสิทธิภาพของ V-JEPA2):** พี่แฮปตั้งคำถามสำคัญว่า "เราจะพิสูจน์ได้อย่างไรว่าโมเดล JEPA เวิร์คกับงาน Locomotion จริงๆ?" เพราะคีย์หลักของไปป์ไลน์นี้คือ JEPA ต้องให้ข้อมูลที่สามารถ **"ทำนายสถานะปัจจุบันและอนาคต (Predict present and future state) ของหุ่นยนต์ใน Simulation ได้อย่างถูกต้อง"** หากโมเดลแยกแยะฟีเจอร์การเคลื่อนที่ไม่ได้ งานนี้จะไปต่อไม่ได้เลย
    *   *แนวทางตอบ:* ไออุ่นได้ตอบไว้ว่า จะพิสูจน์โดยให้โมเดลลองทายจังหวะการเคลื่อนที่ เช่น ทายว่าเท้าแตะพื้น (Foot Contact) ถูกต้องหรือไม่
*   **คำถามจากพี่แฮป (เรื่องนิยามคำว่า "Visual"):** พี่แฮปทักท้วงว่าการใช้คำว่า "Visual observation" อาจทำให้กรรมการที่ฟังครั้งแรกเข้าใจผิดว่าเป็นการใช้ **"กล้องที่ติดอยู่ที่ตาของหุ่นยนต์ (First-person view)"** ไปทำนายสภาพแวดล้อม
    *   *แนวทางแก้ไข:* ต้องเน้นย้ำและอธิบายให้ชัดเจนตั้งแต่แรกว่า ระบบของเราคือ **"ผู้สังเกตการณ์บุคคลที่สาม (Third-person observer)"** ที่มองสภาพแวดล้อมของหุ่นยนต์จากมุมมองภายนอก

**2. ฟีดแบคด้านการเล่าเรื่องเพื่อดึงดูดกรรมการ (Storytelling & Flow)**
*   **อย่ากระโดดข้ามไป World Model ทันที:** อาจารย์โก้แนะนำว่ากรรมการอาจจะตามไม่ทัน ควรปูเรื่องให้เห็นภาพชัดเจนเป็นสเต็ปว่า:
    1. งาน Cross-Morphology ในอดีตต้องใช้ข้อมูลจากภายในตัวหุ่น (Proprioceptive information) เช่น องศาและความเร็วข้อต่อ ซึ่งเก็บได้ยาก
    2. เราจึงตั้งคำถาม (Research Question) ว่า เราสามารถใช้แค่ภาพสังเกตการณ์จากภายนอก (External observation) แทนได้หรือไม่?
    3. การนำข้อมูลภาพจากภายนอกมาใช้ จึงนำไปสู่ความจำเป็นในการ "ทำนายอนาคต (Predict next state)" ซึ่งนี่คือจุดที่ดึงคอนเซปต์ของ **World Model** เข้ามาใช้
*   **ใช้รูปภาพช่วยเล่าเรื่อง:** ควรเพิ่มรูปภาพของหุ่นยนต์หลายๆ รูปแบบ (Morphologies) เพื่อชี้ให้กรรมการเห็นภาพทันทีว่า โครงสร้างที่ต่างกันทำให้เกิดปัญหาในการใช้ข้อมูลการเคลื่อนที่ร่วมกันอย่างไร
*   **ทำตารางเปรียบเทียบ (Comparison Table):** ให้ทำตารางเปรียบเทียบข้อจำกัดให้ชัดเจน ระหว่างงานวิจัยอื่นๆ (ที่ต้องพึ่งพา Proprioceptive feedback) กับงานของเรา (ที่ใช้เพียง Visual observation อย่างเดียว) เพื่อโชว์จุดแข็งของงาน

**3. ความชัดเจนของเป้าหมายและผลลัพธ์ (Outcome Clarity)**
*   **เน้นย้ำผลลัพธ์ปลายทาง:** พี่แฮปแนะนำให้สรุปในสไลด์ให้เคลียร์ว่า ผลลัพธ์สุดท้าย (Outcome) ของงานนี้คือการได้ **"Latent Action"** ซึ่งเปรียบเสมือนเป็น **"Unified Policy"** ที่จะนำไปขับเคลื่อนหุ่นยนต์รูปร่างต่างๆ (Cross-Morphology) ได้
*   **ต้องมีภาพ Validation Pipeline สรุปจบ:** อาจารย์โก้รีเควสต์ให้วาดไปป์ไลน์การทดสอบในตอนท้ายให้เป็นรูปธรรมว่า ภาพรวมการทำงานคืออะไร เช่น นำภาพ Snapshot ของแมลงขายาว -> เข้าโมเดลเพื่อสกัด Latent space -> แล้วถ่ายโอนไปให้ขากลางหรือขาสั้นเดินได้อย่างไร (แสดงให้เห็นว่าจะเทรนหรือไม่เทรนอย่างไร)

**4. ฟีดแบคเพื่อปรับแก้สไลด์แบบจุดต่อจุด (Specific Slide Corrections จากพี่นาย)**
*   **สไลด์ 17 (สมการตัวชี้วัดความสำเร็จ):** การเขียนสมการตัวอักษรว่า `Morphology decoder < Morphology decoder (Latent vs Raw)` ดูเข้าใจยากและสื่อสารไม่ชัดเจน พี่แฮปแนะนำให้เขียนสื่อสารไปตรงๆ เลยว่า **"Latent action จะต้องไม่ยึดติดกับ morphology ใดเป็นพิเศษ"** (อธิบายว่าตัวแปรของเราต้อง decode ออกมาเป็น morphology ใดๆ ได้น้อยที่สุด)
*   **สไลด์ 18-19 (สถาปัตยกรรม V-JEPA2):** ในช่วงที่อธิบายผลการตรวจสอบโมเดล JEPA ควรเอาแผนภาพสถาปัตยกรรม (Architecture) ของมันขึ้นมาโชว์ประกบด้วยเสมอ เพราะโครงสร้างมันใหญ่และซับซ้อน กรรมการอาจจะลืมไปแล้วว่าคุณกำลังพูดถึงการทดสอบบล็อกไหนของระบบอยู่
